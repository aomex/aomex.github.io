# Product i18n

[WebApp.language](/en/web/#language) and [ConsoleApp.language](/en/console/#language) control the **framework**: body/query validation failures and built-in prompts. Product greetings, business error codes, and email templates are not in that set—you maintain message packs and build outbound strings with `i18n.t(...)`.

Keep the two layers separate: current language still comes from the App (you usually do not parse `Accept-Language` yourself); do not stuff product copy into framework `language` so framework upgrades stay mergeable.

Below: one Chinese master catalog → routes that call `t` → missing keys caught at type time.

## Step 1: Define the master key tree

Write the master pack in Chinese (or your primary language) with `I18n.define`. Every other locale must match that tree.

```typescript
// src/i18n/locales/zh-cn.ts
import { I18n } from '@aomex/common';

export const zh = I18n.define({ // [!code highlight]
  greeting: '你好，{{name}}',
  errors: {
    notFound: '找不到资源',
    quotaExceeded: '今日额度已用完',
  },
});
```

`{{name}}` is a template placeholder—the name you pass to `t` must match, or you will see placeholders or empty segments at runtime.

## Step 2: Align the second locale with `satisfies`

Do not hand-write a “close enough” object—use `I18n.satisfies(zh).define`. Missing or extra keys often fail in **types** before production.

```typescript
// src/i18n/locales/en-us.ts
import { I18n } from '@aomex/common';
import { zh } from '@/i18n/locales/zh-cn';

export const en = I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'Hello, {{name}}',
  errors: {
    notFound: 'Not found',
    quotaExceeded: 'Daily quota exceeded',
  },
});
```

Delete `errors.notFound` in the editor—you should see a type mismatch with the master immediately.

## Step 3: Assemble with `createI18n`

```typescript
// src/i18n/index.ts
import { createI18n } from '@aomex/common';
import { zh } from '@/i18n/locales/zh-cn';
import { en } from '@/i18n/locales/en-us';

export const i18n = createI18n({
  zh,
  en,
  load: (file) => { // [!code highlight]
    return import(new URL(`./locales/${file}.js`, import.meta.url).href);
  },
});
```

- `zh` / `en`: languages bundled synchronously at startup  
- `load`: on-demand async locales (next step); file naming below  

Convention: `locales/` holds copy only; `index.ts` only wires—same layout as framework i18n, easy for the next person.

## Step 4: Use in routes

```typescript
import { rule } from '@aomex/common';
import { query, Router } from '@aomex/web';
import { i18n } from '@/i18n';

const router = new Router();

router.get('/hello', {
  mount: [query({ name: rule.string().default('guest') })],
  action: async (ctx) => {
    ctx.send({
      message: i18n.t('greeting', { name: ctx.query.name }), // [!code highlight]
    });
  },
});

router.post('/consume', {
  action: async (ctx) => {
    if (!(await hasQuota(ctx))) {
      ctx.throw(429, i18n.t('errors.quotaExceeded'));
    }
  },
});
```

The first argument to `t` is the key path (`'errors.quotaExceeded'`); the second is template data. Wrong keys show up in completion; mapping to App language is normalized on the framework side—configure language codes like `zh-CN` / `en-US` with hyphens.

Change App `language` (or negotiate via headers) and hit `/hello`—greeting should follow **without** reading `Accept-Language` in the action.

## Step 5: On-demand third locale

For small languages you do not want in the main bundle, use files `load` can resolve: lowercase filename + **`export default`**.

```typescript
// src/i18n/locales/ja-jp.ts
import { I18n } from '@aomex/common';
import { zh } from '@/i18n/locales/zh-cn';

export default I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'こんにちは、{{name}}',
  errors: {
    notFound: 'リソースが見つかりません',
    quotaExceeded: '本日の上限に達しました',
  },
});
```

::: warning
On-demand files must use `export default`. `export const ja = ...` will not match `load`.  
In bare scripts / unit tests, if the locale is not loaded yet, call `ensureI18nLanguage` (or your wrapper) per type hints before `t`.
:::

## Boundaries: framework `language` vs custom validators

| Copy type | Where |
| --- | --- |
| Built-in messages for `rule.string()` failures | App `language` |
| Product sentences like “daily quota exceeded” | This page’s `i18n` |
| Custom validator `deny` needing product copy | `import { i18n }` inside `deny`, then `t` |

See [Custom validators](/en/advanced/validator). Do not put business keys in the framework language table, or use the framework table as product copy.

## What you usually see when something is wrong

| Symptom | Likely cause |
| --- | --- |
| Second locale fails types | Skipped `satisfies(zh).define`, or keys do not match master |
| Runtime shows `{{name}}` | `t` param names do not match template |
| Async locale always falls back | Filename case / missing `export default` / load not awaited |
| Validation 400 still Chinese, product English | Expected: two tables—check App `language` vs `i18n` separately |
