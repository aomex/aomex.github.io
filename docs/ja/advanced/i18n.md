# アプリケーションの i18n

[WebApp.language](/ja/web/#language) / [ConsoleApp.language](/ja/console/#language) が管轄するのは**フレームワーク**側です：body / query の検証失敗メッセージや組み込み文言の言語。製品の挨拶、業務エラーコード、メールテンプレートはその枠外 — 自前で文案バンドルを用意し、`i18n.t(...)` で外向き文字列を組み立てます。

二つの責務を分けます。現在言語は引き続き App が駆動（通常は自分で `Accept-Language` を解析しない）。製品文案をフレームワークの `language` に詰め込まない — フレームワーク更新時のマージが楽になります。

以下、「中国語マスター 1 本」から「ルートで `t` が使え、欠けたキーが型で分かる」まで進めます。

## ステップ 1：マスターのキーツリーを決める

まず中国語（または主言語）パックを書き、`I18n.define` で全キーを固定します。他言語はこのツリーに揃えます。

```typescript
// src/i18n/locales/zh-cn.ts
import { I18n } from '@aomex/common';

export const zh = I18n.define({ // [!code highlight]
  greeting: '你好，{{name}}',
  errors: {
    notFound: '找不到资源',
    quotaExceeded: '今日额度已用完',
  },
});
```

`{{name}}` はテンプレートのプレースホルダーです。`t` 呼び出しの引数名と一致させないと、実行時にプレースホルダや空文字が残ります。

## ステップ 2：第二言語は satisfies で揃える

「だいたい同じ」オブジェクトを手書きしない — `I18n.satisfies(zh).define` を使うと、欠けたキー・余分なキーが**型**で怒られ、リリース後に翻訳漏れに気づくより楽です。

```typescript
// src/i18n/locales/en-us.ts
import { I18n } from '@aomex/common';
import { zh } from '@/i18n/locales/zh-cn';

export const en = I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'Hello, {{name}}',
  errors: {
    notFound: 'Not found',
    quotaExceeded: 'Daily quota exceeded',
  },
});
```

`errors.notFound` を消してみる — エディタがすぐマスター不一致を示すはずです。

## ステップ 3：createI18n で組み立て

```typescript
// src/i18n/index.ts
import { createI18n } from '@aomex/common';
import { zh } from '@/i18n/locales/zh-cn';
import { en } from '@/i18n/locales/en-us';

export const i18n = createI18n({
  zh,
  en,
  load: (file) => { // [!code highlight]
    return import(new URL(`./locales/${file}.js`, import.meta.url).href);
  },
});
```

- `zh` / `en`：起動時に同期バンドルする言語
- `load`：オンデマンドの非同期言語（次のステップ）；ファイル名規則は下記

ディレクトリ習慣：`locales/` は文案のみ、`index.ts` は組み立てだけ — フレームワーク内 i18n と同じで、後から探しやすいです。

## ステップ 4：ルートで使う

```typescript
import { rule } from '@aomex/common';
import { query, Router } from '@aomex/web';
import { i18n } from '@/i18n';

const router = new Router();

router.get('/hello', {
  mount: [query({ name: rule.string().default('guest') })],
  action: async (ctx) => {
    ctx.send({
      message: i18n.t('greeting', { name: ctx.query.name }), // [!code highlight]
    });
  },
});

router.post('/consume', {
  action: async (ctx) => {
    if (!(await hasQuota(ctx))) {
      ctx.throw(429, i18n.t('errors.quotaExceeded'));
    }
  },
});
```

`t` の第一引数はキーパス（`'errors.quotaExceeded'`）、第二はテンプレート引数。キー誤りは補完で確認。App の現在言語との対応はフレームワーク側が正規化します。言語コードは `zh-CN` / `en-US` のようなハイフン形式。

App の `language`（またはヘッダー交渉）を変えて `/hello` を叩くと、挨拶が追従するはず — action 内で `Accept-Language` を読む必要は**ありません**。

## ステップ 5：第三言語をオンデマンド読み込み

小言語をメインバンドルに載せたくないとき、`load` が解決できるファイルへ：`export default` の小文字ファイル名。

```typescript
// src/i18n/locales/ja-jp.ts
import { I18n } from '@aomex/common';
import { zh } from '@/i18n/locales/zh-cn';

export default I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'こんにちは、{{name}}',
  errors: {
    notFound: 'リソースが見つかりません',
    quotaExceeded: '本日の上限に達しました',
  },
});
```

::: warning
オンデマンドファイルは **`export default` 必須**。`export const ja = ...` だと `load` と合いません。  
素のスクリプト / 単体テストで言語の読み込みが終わっていないときは、型ヒントどおり `ensureI18nLanguage`（またはプロジェクトのラッパー）を先に呼び、その後 `t`。
:::

## フレームワーク language とカスタムバリデータの境界

| 文案の種類 | 置き場所 |
| --- | --- |
| `rule.string()` 失敗の組み込みメッセージ | App `language` |
| 「今日の枠を使い切った」など製品文 | 本ページの `i18n` |
| カスタムバリデータの `deny` で製品文 | `deny` 内で `import { i18n }` して `t` |

[カスタムバリデータ](/ja/advanced/validator) を参照。業務キーをフレームワーク言語表に入れず、フレームワーク表で製品文を代用しないでください。

## 設定ミスで起きがちなこと

| 現象 | 原因のことが多い |
| --- | --- |
| 第二言語で型エラー | `satisfies(zh).define` を使っていない、またはキーがマスターと不一致 |
| 実行時に `{{name}}` が残る | `t` の引数名とテンプレート不一致 |
| 非同期言語がずっとフォールバック | ファイル名の大小文字 / `export default` なし / 読み込み完了前に `t` |
| 検証 400 は中国語のまま、業務文だけ英語 | 正常：二つの表。App language と `i18n` を別々に確認 |
