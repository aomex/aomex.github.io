# ビジネス向け i18n

[WebApp.language](/ja/web/#language) / [ConsoleApp.language](/ja/console/#language) が管るのは**フレームワーク**側：body / query 検証失敗や組み込みメッセージの言語。製品の挨拶文、業務エラーコード、メールテンプレートはその枠外——自分で文言パッケージを作り、`i18n.t(...)` で外向き文字列を組み立てる。

役割を分ける：現在言語は引き続き App が駆動（ふつう `Accept-Language` を自分で解析しない）。製品文言をフレームワークの `language` 設定に混ぜない——フレームワーク更新時にマージしやすい。

以下、「中国語マスター1枚」から「ルートで t でき、欠けたキーは型段階で気づける」まで。

## ステップ1：マスターのキーツリーを決める

まず中国語（または主言語）パッケージを書き、`I18n.define` で全キーを固定する。他言語はこのツリーに揃える。

```typescript
// src/i18n/locales/zh-cn.ts
import { I18n } from '@aomex/common';

export const zh = I18n.define({ // [!code highlight]
  greeting: '你好，{{name}}',
  errors: {
    notFound: '找不到资源',
    quotaExceeded: '今日额度已用完',
  },
});
```
`{{name}}` はテンプレートプレースホルダ。`t` 呼び出しの引数名は一致させること。さもないと実行時にプレースホルダや空文字が露出する。

## ステップ2：第二言語は satisfies で揃える

「だいたい同じ」オブジェクトを手書きしない——`I18n.satisfies(zh).define` を使うと、キーの不足・余分は**型**で怒られることが多く、本番で翻訳漏れに気づくより楽。

```typescript
// src/i18n/locales/en-us.ts
import { I18n } from '@aomex/common';
import { zh } from './zh-cn.js';

export const en = I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'Hello, {{name}}',
  errors: {
    notFound: 'Not found',
    quotaExceeded: 'Daily quota exceeded',
  },
});
```
`errors.notFound` を消してみる：エディタがすぐマスターと不一致を示すはず。

## ステップ3：createI18n で組み立て

```typescript
// src/i18n/index.ts
import { createI18n } from '@aomex/common';
import { zh } from './locales/zh-cn.js';
import { en } from './locales/en-us.js';

export const i18n = createI18n({
  zh,
  en,
  load: (file) => { // [!code highlight]
    return import(new URL(`./locales/${file}.js`, import.meta.url).href);
  },
});
```
- `zh` / `en`：起動時に同梱する言語  
- `load`：非同期で必要な言語（次のステップ）。ファイル名ルールは下記  

ディレクトリ習慣：`locales/` に文案のみ、`index.ts` は組み立てだけ——フレームワーク内 i18n と同じ構造で、後から見つけやすい。

## ステップ4：ルートで使う

```typescript
import { rule } from '@aomex/common';
import { query, Router } from '@aomex/web';
import { i18n } from '../i18n/index.js';

const router = new Router();

router.get('/hello', {
  mount: [query({ name: rule.string().default('guest') })],
  action: async (ctx) => {
    ctx.send({
      message: i18n.t('greeting', { name: ctx.query.name }), // [!code highlight]
    });
  },
});

router.post('/consume', {
  action: async (ctx) => {
    if (!(await hasQuota(ctx))) {
      ctx.throw(429, i18n.t('errors.quotaExceeded'));
    }
  },
});
```
`t` の第一引数はキーパス（`'errors.quotaExceeded'`）、第二はテンプレート引数。キーを間違えると補完で分かる。App の現在言語との対応はフレームワーク側が正規化。言語コードは `zh-CN` / `en-US` のようなハイフン形式。

App の `language`（またはリクエストヘッダ協議）を変えて `/hello` を叩くと、挨拶が変わるはず——**action で自分が `Accept-Language` を読む必要はない**。

## ステップ5：第三言語をオンデマンド読み込み

小さな言語をメインバンドルに入れたくないとき、`load` が解決するファイルへ：ファイル名は小文字 + **`export default`**。

```typescript
// src/i18n/locales/ja-jp.ts
import { I18n } from '@aomex/common';
import { zh } from './zh-cn.js';

export default I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'こんにちは、{{name}}',
  errors: {
    notFound: 'リソースが見つかりません',
    quotaExceeded: '本日の上限に達しました',
  },
});
```
::: warning
オンデマンドファイルは `export default` 必須。`export const ja = ...` だと `load` と合わない。  
裸スクリプト / 単体テストで言語読み込み前なら、型ヒントに従い `ensureI18nLanguage`（またはプロジェクトのラッパー）を先に呼んでから `t`。
:::

## フレームワーク language とカスタムバリデータの境界

| 文言の種類 | 置き場所 |
| --- | --- |
| `rule.string()` 失敗の組み込みメッセージ | App `language` |
| 「本日の枠を使い切った」など製品文 | 本ページの `i18n` |
| カスタムバリデータの `deny` に製品文 | `deny` 内で `import { i18n }` して `t` |

[カスタムバリデータ](/ja/advanced/validator) 参照。業務キーをフレームワーク言語表に入れない。フレームワーク表を製品文案の代わりにしない。

## 設定を間違えると

| 現象 | 多くは原因 |
| --- | --- |
| 第二言語で型エラー | `satisfies(zh).define` していない、またはキーがマスターと不一致 |
| 実行時に `{{name}}` が露出 | `t` の引数名とテンプレート不一致 |
| 非同期言語がずっとフォールバック | ファイル名の大小文字 / `export default` 未使用 / 読み込み完了を待っていない |
| 検証 400 は中国語のまま、業務文は英語 | 正常：二系統の表。App language と `i18n` をそれぞれ確認 |
