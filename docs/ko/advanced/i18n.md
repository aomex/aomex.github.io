# 제품 i18n

[WebApp.language](/ko/web/#language)와 [ConsoleApp.language](/ko/console/#language)는 **프레임워크**를 제어합니다. body/query 검증 실패·내장 프롬프트입니다. 제품 인사말, 업무 오류 코드, 이메일 템플릿은 여기 없습니다. 메시지 팩을 직접 두고 `i18n.t(...)`로 문자열을 만듭니다.

두 층을 분리하세요. 현재 언어는 여전히 App에서 옵니다(`Accept-Language`를 직접 파싱할 일은 보통 없음). 제품 문구를 프레임워크 `language`에 넣지 마세요. 프레임워크 업그레이드 병합이 쉬워집니다.

아래: 중국어 마스터 카탈로그 하나 → `t`를 쓰는 라우트 → 누락 키를 타입으로 잡기.

## 1단계: 마스터 키 트리

`I18n.define`로 마스터 팩을 씁니다. 다른 로케일은 그 트리와 맞아야 합니다.

```typescript
// src/i18n/locales/zh-cn.ts
import { I18n } from '@aomex/common';

export const zh = I18n.define({ // [!code highlight]
  greeting: '你好，{{name}}',
  errors: {
    notFound: '找不到资源',
    quotaExceeded: '今日额度已用完',
  },
});
```

`{{name}}`은 템플릿 자리표시자입니다. `t`에 넘기는 이름과 같아야 하며, 아니면 런타임에 플레이스홀더나 빈 구간이 보입니다.

## 2단계: `satisfies`로 두 번째 로케일 맞추기

비슷한 객체를 손으로 쓰지 마세요. `I18n.satisfies(zh).define`을 쓰세요. 키가 빠지거나 남으면 **타입**에서 먼저 실패하는 경우가 많습니다.

```typescript
// src/i18n/locales/en-us.ts
import { I18n } from '@aomex/common';
import { zh } from './zh-cn.js';

export const en = I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'Hello, {{name}}',
  errors: {
    notFound: 'Not found',
    quotaExceeded: 'Daily quota exceeded',
  },
});
```

편집기에서 `errors.notFound`를 지우면 마스터와 즉시 타입 불일치가 나와야 합니다.

## 3단계: `createI18n`으로 조립

```typescript
// src/i18n/index.ts
import { createI18n } from '@aomex/common';
import { zh } from './locales/zh-cn.js';
import { en } from './locales/en-us.js';

export const i18n = createI18n({
  zh,
  en,
  load: (file) => { // [!code highlight]
    return import(new URL(`./locales/${file}.js`, import.meta.url).href);
  },
});
```

- `zh` / `en`: 시작 시 동기 번들  
- `load`: 필요 시 비동기 로케일(다음 단계); 파일 이름 규칙은 아래  

관례: `locales/`는 문구만, `index.ts`는 연결만 — 프레임워크 i18n과 비슷해 다음 사람이 읽기 쉽습니다.

## 4단계: 라우트에서 사용

```typescript
import { rule } from '@aomex/common';
import { query, Router } from '@aomex/web';
import { i18n } from '../i18n/index.js';

const router = new Router();

router.get('/hello', {
  mount: [query({ name: rule.string().default('guest') })],
  action: async (ctx) => {
    ctx.send({
      message: i18n.t('greeting', { name: ctx.query.name }), // [!code highlight]
    });
  },
});

router.post('/consume', {
  action: async (ctx) => {
    if (!(await hasQuota(ctx))) {
      ctx.throw(429, i18n.t('errors.quotaExceeded'));
    }
  },
});
```

`t`의 첫 인자는 키 경로(`'errors.quotaExceeded'`), 두 번째는 템플릿 데이터입니다. 잘못된 키는 자동 완성에서 드러납니다. App language와 매핑은 프레임워크가 정규화합니다. `zh-CN` / `en-US`처럼 하이픈 로케일을 쓰세요.

App `language`(또는 헤더 협상)를 바꾸고 `/hello`를 치면 action에서 `Accept-Language`를 읽지 않아도 인사말이 따라와야 합니다.

## 5단계: 필요 시 세 번째 로케일 지연 로드

메인 번들에 넣기 싫은 작은 언어는 `load`가 찾는 파일로: 소문자 파일명 + **`export default`**.

```typescript
// src/i18n/locales/ja-jp.ts
import { I18n } from '@aomex/common';
import { zh } from './zh-cn.js';

export default I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'こんにちは、{{name}}',
  errors: {
    notFound: 'リソースが見つかりません',
    quotaExceeded: '本日の上限に達しました',
  },
});
```

::: warning
지연 로드 파일은 `export default`여야 합니다. `export const ja = ...`는 `load`와 맞지 않습니다.  
스크립트/단위 테스트에서 로케일이 아직 없으면 `t` 전에 `ensureI18nLanguage`(또는 래퍼)를 타입 힌트대로 호출하세요.
:::

## 경계: 프레임워크 `language` vs 사용자 검증기

| 문구 종류 | 위치 |
| --- | --- |
| `rule.string()` 등 내장 검증 실패 메시지 | App `language` |
| 「일일 할당량 초과」 같은 제품 문장 | 이 페이지 `i18n` |
| 제품 문구가 필요한 사용자 검증기 `deny` | `deny` 안에서 `import { i18n }` 후 `t` |

[사용자 정의 검증기](/ko/advanced/validator). 업무 키를 프레임워크 language 표에 넣거나 그 표를 제품 문구로 쓰지 마세요.

## 잘못됐을 때 흔한 증상

| 증상 | 원인 추정 |
| --- | --- |
| 두 번째 로케일 타입 실패 | `satisfies(zh).define` 생략, 키 불일치 |
| 런타임에 `{{name}}` 그대로 | `t` 매개변수 이름이 템플릿과 다름 |
| 비동기 로케일 항상 폴백 | 파일명 대소문자 / `export default` 누락 / load 미대기 |
| 검증 400은 중국어, 제품은 영어 | 정상: 두 표 — App `language`와 `i18n`을 각각 확인 |
