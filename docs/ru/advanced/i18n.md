# Локализация приложения (i18n)

[WebApp.language](/ru/web/#language) и [ConsoleApp.language](/ru/console/#language) отвечают за **фреймворк**: язык сообщений при ошибках body/query и встроенных подсказок. Приветствия продукта, бизнес-коды ошибок и шаблоны писем туда не входят — заведите свои пакеты строк и собирайте внешний текст через `i18n.t(...)`.

Две зоны ответственности раздельно: текущий язык по-прежнему задаёт App (обычно без ручного разбора `Accept-Language`); продуктовые фразы не пихайте в `language` фреймворка — так проще сливать обновления.

Ниже — от «одного мастера на китайском» до «`t` в маршруте и пропущенные ключи видны на этапе типов».

## Шаг 1: дерево ключей мастера

Сначала пакет на китайском (или основном языке) и `I18n.define` для всех ключей. Остальные языки выравниваются по этому дереву.

```typescript
// src/i18n/locales/zh-cn.ts
import { I18n } from '@aomex/common';

export const zh = I18n.define({ // [!code highlight]
  greeting: '你好，{{name}}',
  errors: {
    notFound: '找不到资源',
    quotaExceeded: '今日额度已用完',
  },
});
```

`{{name}}` — плейсхолдер шаблона; имя аргумента в вызове `t` должно совпадать, иначе в рантайме останутся плейсхолдеры или пустые куски.

## Шаг 2: второй язык через satisfies

Не пишите «похожий» объект руками — `I18n.satisfies(zh).define`: лишние и недостающие ключи часто ловятся на **типах**, а не в проде.

```typescript
// src/i18n/locales/en-us.ts
import { I18n } from '@aomex/common';
import { zh } from '@/i18n/locales/zh-cn';

export const en = I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'Hello, {{name}}',
  errors: {
    notFound: 'Not found',
    quotaExceeded: 'Daily quota exceeded',
  },
});
```

Попробуйте убрать `errors.notFound` — редактор сразу покажет расхождение с мастером.

## Шаг 3: сборка createI18n

```typescript
// src/i18n/index.ts
import { createI18n } from '@aomex/common';
import { zh } from '@/i18n/locales/zh-cn';
import { en } from '@/i18n/locales/en-us';

export const i18n = createI18n({
  zh,
  en,
  load: (file) => { // [!code highlight]
    return import(new URL(`./locales/${file}.js`, import.meta.url).href);
  },
});
```

- `zh` / `en` — языки, синхронно в бандле при старте
- `load` — отложенная подгрузка (следующий шаг); правила имён файлов ниже

Структура: `locales/` только строки, `index.ts` только сборка — как во внутреннем i18n фреймворка, проще искать.

## Шаг 4: в маршрутах

```typescript
import { rule } from '@aomex/common';
import { query, Router } from '@aomex/web';
import { i18n } from '@/i18n';

const router = new Router();

router.get('/hello', {
  mount: [query({ name: rule.string().default('guest') })],
  action: async (ctx) => {
    ctx.send({
      message: i18n.t('greeting', { name: ctx.query.name }), // [!code highlight]
    });
  },
});

router.post('/consume', {
  action: async (ctx) => {
    if (!(await hasQuota(ctx))) {
      ctx.throw(429, i18n.t('errors.quotaExceeded'));
    }
  },
});
```

Первый аргумент `t` — путь ключа (`'errors.quotaExceeded'`), второй — параметры шаблона. Ошибки ключа видны по автодополнению. Связь с текущим языком App нормализует фреймворк; коды языка — с дефисом: `zh-CN`, `en-US`.

Поменяйте `language` в App (или согласование по заголовку) и дерните `/hello` — приветствие должно смениться **без** ручного чтения `Accept-Language` в action.

## Шаг 5: третий язык по требованию

Редкие языки не кладите в основной бандл: файл, который резолвит `load` — имя в нижнем регистре и **`export default`**.

```typescript
// src/i18n/locales/ja-jp.ts
import { I18n } from '@aomex/common';
import { zh } from '@/i18n/locales/zh-cn';

export default I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'こんにちは、{{name}}',
  errors: {
    notFound: 'リソースが見つかりません',
    quotaExceeded: '本日の上限に達しました',
  },
});
```

::: warning
Для отложенной загрузки нужен **`export default`**. Вариант `export const ja = ...` не стыкуется с `load`.  
В голых скриптах / тестах, если язык ещё не подгружен, сначала вызовите `ensureI18nLanguage` (или обёртку проекта) по подсказке типов, затем `t`.
:::

## Граница с language фреймворка и кастомными валидаторами

| Тип текста | Где хранить |
| --- | --- |
| Встроенные сообщения при сбое `rule.string()` | `language` в App |
| Продуктовые фразы вроде «дневной лимит исчерпан» | `i18n` с этой страницы |
| Продуктовый текст в `deny` кастомного валидатора | в `deny` сделайте `import { i18n }` и `t` |

См. [кастомный валидатор](/ru/advanced/validator). Не смешивайте бизнес-ключи с таблицей фреймворка и не подменяйте продуктовый текст таблицей фреймворка.

## Типичные симптомы ошибок

| Симптом | Чаще всего |
| --- | --- |
| Ошибка типов на втором языке | нет `satisfies(zh).define` или ключи не совпадают с мастером |
| В рантайме остаётся `{{name}}` | имя аргумента `t` не совпадает с шаблоном |
| Отложенный язык всегда fallback | регистр имени файла / нет `export default` / `t` до окончания загрузки |
| 400 при валидации по-китайски, бизнес-текст по-английски | нормально: две таблицы; смотрите App language и `i18n` отдельно |
