# Интернационализация приложения

[WebApp.language](/ru/web/#language) / [ConsoleApp.language](/ru/console/#language) отвечают за сторону **framework**: сбой проверки тела/запроса, встроенная подсказка, какой язык использовать. Приветствия к продуктам, коды бизнес-ошибок и шаблоны электронных писем не включены в этот набор — вам придется создать собственный пакет копирайтинга, использовать `i18n.t(...)` Назовите внешнюю строку.

Два набора обязанностей разделены: текущий язык по-прежнему управляется приложением (как правило, нет необходимости анализировать его самостоятельно). `Accept-Language`); не размещайте копию продукта в рамке ` language`Конфигурация, ее можно объединить только при обновлении платформы.

Далее, от «китайской мастер-копии» до «t можно найти в маршрутизации, а недостающие ключи можно найти на этапе типа».

## Шаг 1. Определите родительское дерево ключей.

Сначала напишите пакет на китайском (или вашем основном языке), используя ` I18n.define`Установить все ключи. Другие языки должны соответствовать этому дереву.

```typescript
// src/i18n/locales/zh-cn.ts
import { I18n } from '@aomex/common';

export const zh = I18n.define({ // [!code highlight]
  greeting: '你好，{{name}}',
  errors: {
    notFound: '找不到资源',
    quotaExceeded: '今日额度已用完',
  },
});
```

`{{name}}` — это заполнитель шаблона — имя, которому вы передаете ` t ` должно совпадать, иначе во время выполнения вы увидите заполнители или пустые сегменты.

## Шаг 2. Совместите вторую локаль с ` satisfies `

Не пишите от руки объект «достаточно близко» — используйте ` I18n.satisfies(zh).define `. Отсутствующие или лишние ключи часто выходят из строя в **типах** перед производством.

```typescript
// src/i18n/locales/en-us.ts
import { I18n } from '@aomex/common';
import { zh } from './zh-cn.js';

export const en = I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'Hello, {{name}}',
  errors: {
    notFound: 'Not found',
    quotaExceeded: 'Daily quota exceeded',
  },
});
```

Удалить ` errors.notFound ` в редакторе — вы должны сразу увидеть несоответствие типа мастеру.

## Шаг 3: Соберите ` createI18n `

```typescript
// src/i18n/index.ts
import { createI18n } from '@aomex/common';
import { zh } from './locales/zh-cn.js';
import { en } from './locales/en-us.js';

export const i18n = createI18n({
  zh,
  en,
  load: (file) => { // [!code highlight]
    return import(new URL(`./locales/${file}.js `, import.meta.url).href);
  },
});
```

- ` zh ` / ` en `: языки объединяются синхронно при запуске  
- ` load `: асинхронные локали по требованию (следующий шаг); название файла ниже  

Конвенция: ` locales/` содержит только копию; ` index.ts ` только провода — та же схема, что и у каркаса i18n, удобна для любого человека.

## Шаг 4: Использование в маршрутах

```typescript
import { rule } from '@aomex/common';
import { query, Router } from '@aomex/web';
import { i18n } from '../i18n/index.js';

const router = new Router();

router.get('/hello', {
  mount: [query({ name: rule.string().default('guest') })],
  action: async (ctx) => {
    ctx.send({
      message: i18n.t('greeting', { name: ctx.query.name }), // [!code highlight]
    });
  },
});

router.post('/consume', {
  action: async (ctx) => {
    if (!(await hasQuota(ctx))) {
      ctx.throw(429, i18n.t('errors.quotaExceeded'));
    }
  },
});
```

Первый аргумент в пользу ` t ` это ключевой путь (`'errors.quotaExceeded'`); второй — данные шаблона. В завершении отображаются неправильные ключи; сопоставление с языком приложения нормализуется на стороне платформы — настройте языковые коды, например ` zh-CN ` / ` en-US ` с дефисами.

Изменить приложение ` language ` (или договоритесь через заголовки) и нажмите `/hello `— приветствие должно следовать **без** чтения ` Accept-Language ` в действии.

## Шаг 5: Третья локаль по требованию

Для небольших языков, которые вы не хотите использовать в основном пакете, используйте файлы ` load ` можно разрешить: имя файла в нижнем регистре + **` export default `**.

```typescript
// src/i18n/locales/ja-jp.ts
import { I18n } from '@aomex/common';
import { zh } from './zh-cn.js';

export default I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'こんにちは、{{name}}',
  errors: {
    notFound: 'リソースが見つかりません',
    quotaExceeded: '本日の上限に達しました',
  },
});
```

::: предупреждение
Файлы по требованию должны использовать ` export default `. ` export const ja = ... ` не будет соответствовать ` load `.  
В голых сценариях/юнит-тестах, если локаль еще не загружена, вызовите ` ensureI18nLanguage ` (или вашу оболочку) для каждого типа подсказок перед ` t `.
:::

## Границы: рамки ` language ` против пользовательских валидаторов

| Тип копирования | Где |
| --- | --- |
| Встроенные сообщения для ` rule.string()` неудачи | Приложение ` language ` |
| Предложения о продуктах, такие как «дневная квота превышена» | Эта страница ` i18n ` |
| Пользовательский валидатор ` deny ` нужна копия продукта | ` import { i18n }` внутри ` deny `, затем ` t ` |

См. [Пользовательские валидаторы](/ru/advanced/validator). Не помещайте бизнес-ключи в языковую таблицу платформы и не используйте таблицу платформы в качестве копии продукта.

## Что вы обычно видите, когда что-то не так

| Симптом | Вероятная причина |
| --- | --- |
| Вторая локаль не дает типов | Пропущено ` satisfies(zh).define `, или ключи не соответствуют мастеру |
| Шоу во время выполнения `{{name}}` | ` t ` имена параметров не соответствуют шаблону |
| Асинхронная локаль всегда возвращается | Регистр имени файла/отсутствует ` export default ` / загрузка не ожидается |
| Валидация 400 все еще китайская, продукт английский | Ожидается: две таблицы — проверьте приложение. ` language ` vs ` i18n` отдельно |
