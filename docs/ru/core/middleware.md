# Middleware

Добавьте сквозную или групповую логику: «сделать что-то при запросе и завершить после `next()`», а в action используйте поля, которые вы повесили на ` ctx ` (например, ` requestId `).


middleware — это функция: не забудьте дождаться next(), запрос будет продолжать выполняться; вы можете написать часть логики до и после вызова next.

```typescript
import { middleware } from '@aomex/common';

export const withRequestId = middleware.mixin<{
  readonly requestId: string;
}>(async (ctx, next) => { // [!code highlight]
  ctx.requestId = crypto.randomUUID();
  await next();
});
```

::: warning
Последующее middleware и бизнес полагаются на await next(); если аутентификация не удалась и вы хотите сократить ее, вы можете оставить ее в покое, но не пропустите ее случайно. Обязательно **await next()**, иначе асинхронные ошибки в нисходящем направлении могут легко стать необработанными. Promise.
:::

использовать ` middleware.mixin<{ … }>`После объявления полей, добавленных вами в ctx, эти атрибуты появятся в завершении более позднего промежуточного программного обеспечения и действий того же маршрута; если вы опустите дженерики и присвоите значения только во время выполнения, компилятор все равно будет относиться к ним так, как будто они не существуют.

```typescript
// action 里
async (ctx) => { // [!code highlight]
  await services.logger.info('请求', { requestId: ctx.requestId });
  return { ok: true };
};
```

Поля соответствующих примесей нескольких промежуточных программ будут объединены в один и тот же ctx с точки зрения типа. Просто добавьте поля в ctx во время выполнения и не пишите миксин. Обобщенные шаблоны могут работать, но TypeScript не может помочь, и при переименовании легко пропустить изменения.

## WebApp.mount

` WebApp.mount `Это вся луковая очередь сайта: CORS, журнал доступа, formatError,` routers(...)`Все выполняются в порядке массива. Чем ближе к переду, тем внешний слой может быть ` await next()`Охватите все последующие маршруты до и после.

```typescript
import { WebApp } from '@aomex/web';
import { routers } from '@aomex/web';
import { withRequestId } from './middlewares/request-id.js';

const app = new WebApp({
  services,
  logger: services.logger,
  language: { mode: 'fixed', language: 'zh-CN' },
  proxyIP: { mode: 'detect' },
  mount: [ // [!code focus:2]
    withRequestId, // [!code highlight]
    routers('./src/routers'),
  ],
});
```

CORS, идентификатор запроса для всего сайта, журналы доступа и другие вещи, которые «необходимы для каждого запроса», поместите ` WebApp.mount`/` ConsoleApp.mount `.

## Router.mount

Используется, когда весь набор URL-адресов использует один и тот же набор логики (унифицированная аутентификация, аудит и formatError под префиксом).` Router({ mount })`, влияет только на путь, зарегистрированный в этом файле, и нет необходимости покрывать весь сайт WebApp.

```typescript
import { Router } from '@aomex/web';

// 某一组资源都要登录（auth 为项目里配好的 Auth 实例）
new Router({ prefix: '/admin', mount: [auth.authenticate('bearer')] });
```

Для унифицированной аутентификации определенного типа ресурсов используйте Router.mount; для общедоступных интерфейсов удалите другой маршрутизатор (не пропускайте их повсюду в одном маршрутизаторе).

## Крепление на один маршрут

одиночный маршрут ` mount`Выполняется только перед этим действием: исключения включают это уникальное тело/запрос, более строгую авторизацию или смешивание с общедоступными интерфейсами в одном маршрутизаторе. Для ежедневной проверки предпочтительно использовать встроенный запрос /body/cors/auth вместо рукописного промежуточного ПО везде.

```typescript
import { rule } from '@aomex/common';
import { body } from '@aomex/web';

router.post('/login', { // [!code focus:11]
  mount: [
    body({ // [!code highlight]
      email: rule.email(),
      password: rule.string(),
    }),
  ],
  action: async (ctx) => {
    ctx.send({ token: '...' });
  },
});
```

## Используйте пропуск для обхода определенных типов запросов.

Некоторые пути или среды не хотят запускать все middleware (для проверки работоспособности не требуется аутентификация, а определенный уровень отключен в тестовой среде), и требуется цепочка существующего промежуточного программного обеспечения. `.skip(...)`: Состояние ` true`прямой ` next()`, не выполняет исходную логику - чем копировать копию ` mount`Низкие эксплуатационные расходы.

Вы можете передать **функцию** (динамически оцениваемую в соответствии с запросом) или передать ее напрямую **` boolean `**(Вы можете решить, прыгать или нет во время компиляции):

```typescript
const authMaybe = auth.authenticate('bearer').skip((ctx) => { // [!code highlight]
  return ctx.request.pathname === '/health';
});

// 测试环境整层关掉：不必再包一层函数
const accessLogMaybe = accessLog().skip(process.env['NODE_ENV'] === 'test');

// 临时禁用某层（等价于挂 mount 时先拿掉）
someMiddleware.skip(true);
```

::: warning
`.skip()`**Не** изменит тип реквизита: при пропуске аутентификации ` ctx.auth ` Тип по-прежнему типа «да»; действие должно самостоятельно обрабатывать нерегистрируемые ветки. При наличии большого количества публичных интерфейсов рекомендуется демонтировать «неаутентифицированный Маршрутизатор» и не вешать ряд пропусков на цепочку аутентификации.
:::

## Используйте dependOn для заимствования восходящих типов

Если при написании промежуточного программного обеспечения вы **предполагаете**, что определенный уровень уже был подвешен ранее (например, аутентификация, полоса ` userId ` middleware), надеясь, что в ` fn ` Заполните эти поля напрямую, но не хотите снова выполнять восходящий поток — используйте ` middleware.dependsOn(上游).web(...)`/`.mixin(...)`/`.console(...)`.

` dependsOn `**Только участвующие типы**: передаваемое вами промежуточное ПО не будет вызываться во время выполнения; фактическое выполнение по-прежнему зависит от предыдущего уровня в последовательности монтирования.

```typescript
import { middleware } from '@aomex/common';

const withUser = middleware.web<{ userId: number }>(async (ctx, next) => {
  ctx.userId = Number(ctx.request.headers['x-user-id']);
  await next();
});

// 假定上游已挂 withUser：这里能补全 ctx.userId，但不会再跑一遍 withUser
export const loadProfile = middleware.dependsOn(withUser).web(async (ctx, next) => { // [!code highlight]
  const profile = await services.user.getProfile(ctx.userId);
  ctx.send(profile);
  await next();
});
```

При монтировании все равно сначала нужно поставить восходящий поток:

```typescript
router.get('/me', {
  mount: [withUser, loadProfile], // [!code highlight]
  action: async () => {},
});
```

Вы также можете перенести завод/` async ` завод (и ` combineServices ` Ленивая загрузка аналогична, здесь она обслуживает только типы). Можно связать несколько раз ` dependsOn `, поля будут сложены вместе.

::: tip
` Middleware.Infer<typeof loadProfile>`**не** принесу это ` dependsOn ` Заимствованный реквизит - по-прежнему выглядит так: «Я не добавлял поля в ctx» для внешнего мира. Тип заимствования влияет на вас только в ` fn `(и тот, что следует сразу за `.skip(ctx => …)`), как видно на ` ctx`.
:::

В повседневной жизни предпочтительнее использовать готовый запрос, тело, корс и различные авторизации; для написания перехватчиков в справке OpenAPI/CLI см. [Пользовательское middleware](/ru/advanced/middleware).
