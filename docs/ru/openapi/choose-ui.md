# Какой docs UI выбрать

aomex предлагает три плагина для документации: [Swagger UI](/ru/openapi/swagger-ui), [Redoc UI](/ru/openapi/redoc-ui), [Scalar UI](/ru/openapi/scalar-ui). Все они читают **один и тот же** OpenAPI-контракт (выложенный `openapi.json` / yaml или `generateOpenapi` в рантайме). Отличаются **удобство чтения** и **возможность дернуть API прямо в браузере**.

На этой странице — выбор по аудитории и сценарию; установка пакета, mount, `uriPrefix` / `enable` и прочие детали — на страницах каждого UI. Как получить контракт — [Генерация OpenAPI](/ru/openapi/).

## Кратко в одну строку

| | [Swagger UI](/ru/openapi/swagger-ui) | [Redoc UI](/ru/openapi/redoc-ui) | [Scalar UI](/ru/openapi/scalar-ui) |
| --- | --- | --- | --- |
| Префикс по умолчанию | `/swagger` | `/redoc` | `/scalar` |
| Проба в странице | да (Try it out) | **нет** | да |
| Чтение | плотная «консоль», много полей | левое меню, удобно для длинного текста | современная вёрстка: читать + дергать |
| Типичная аудитория | разработка, QA при интеграции | продукт, интеграторы, handoff-док | нужно и прочитать, и быстро вызвать |
| Пакет | `@aomex/swagger-ui` | `@aomex/redoc-ui` | `@aomex/scalar-ui` |

Все три — обычное Web-middleware: повесил — появилась страница; типы `ctx` на бизнес-роутах **не меняются**. Если на сайте включён [envelope](/ru/web/envelope), страницы документации автоматически делают `skipEnvelope` и не оборачиваются.

## По сценарию

| Что сейчас делаете | В первую очередь | Почему |
| --- | --- | --- |
| Локально / внутри сети: открыл и дернул API | Swagger или Scalar | Реальные запросы в браузере; если команда привыкла к Try it out — Swagger, для более свежего UI — Scalar |
| URL «инструкции» для интегратора | Redoc | Длинный текст и свёрнутые schema аккуратнее; не рассчитывайте на пробу в странице |
| PDF / «вложение» с описанием API наружу | Redoc | Удобнее для печати и прокрутки |
| Онбординг: сначала прочитать, потом попробовать | Scalar или Redoc + Swagger | Всё на одной странице; или ссылки «читать» и «дергать» раздельно |
| В старом проекте все знают только Swagger | оставить Swagger | Минимум переобучения; ради «другой оболочки» переделывать не обязательно |
| Разная аудитория (продукт + разработка) | **все вместе**, разные `uriPrefix` | Один контракт — несколько UI, см. ниже |

Если сомневаетесь: в разработке хватает **Scalar** или **Swagger**; для внешних объяснений добавьте **Redoc**. Не обязательно «выбрать один» — источник контракта один.

## Границы возможностей (чтобы не промахнуться)

**Проба в странице** — в браузере задать параметры, подставить auth и бить в реальный (или за шлюзом) сервис. Есть у Swagger и Scalar; у Redoc **нет**.

```typescript
// Redoc только показывает контракт — для интеграции откройте Swagger / Scalar / Postman
mount: [
  redocUI({ openapi: './openapi.json', uriPrefix: '/redoc-…' }),
  swaggerUI({ openapi: './openapi.json', uriPrefix: '/swagger-…' }),
  routers('./src/routers'),
],
```

::: warning
Не давайте QA / интеграторам Redoc вместо Swagger «с Try it out». Неправильная ссылка — только чтение, без вызова; можно решить, что API сломан.
:::

Ещё границы:

- UI документации **не** заменяет авторизацию: в публичном интернете это карта API (а с пробой — ещё и вход для Try it out).
- `/swagger`, `/redoc`, `/scalar` по умолчанию легко угадать — в `uriPrefix` лучше **случайная строка**, плюс `enable` / внутренняя сеть / шлюз; подробности на страницах каждого UI.
- При динамическом `openapi: () => generateOpenapi(...)` передайте тот же `app`, что в проде, иначе security / envelope в доке разойдутся с боевой средой.

## Несколько UI на одном сайте

Все три (или любые две) можно повесить на один `WebApp`, **префиксы должны различаться**, контракт — один файл:

```typescript
import { swaggerUI } from '@aomex/swagger-ui';
import { redocUI } from '@aomex/redoc-ui';
import { scalarUI } from '@aomex/scalar-ui';

mount: [ // [!code focus:13]
  swaggerUI({
    openapi: './openapi.json',
    uriPrefix: '/swagger-7c3e9a1f02b48d6e',
  }),
  redocUI({
    openapi: './openapi.json',
    uriPrefix: '/redoc-a1b2c3d4e5f60718',
  }),
  scalarUI({
    openapi: './openapi.json',
    uriPrefix: '/scalar-9f8e7d6c5b4a3210',
  }),
  routers('./src/routers'),
],
```

Если в проде доступ только из внутренней сети или по IP / token, `enable` у всех трёх можно задать одной проверкой (скопировать или вынести в функцию), чтобы ничего не забыть отключить.

## Как связать с «генерацией контракта»

| Откуда контракт | Как UI его читает |
| --- | --- |
| CI: `aomex openapi` на диск | У всех трёх `openapi: './openapi.json'` (или yaml) — после смены роутов перегенерируйте файл |
| Рантайм `generateOpenapi` | `openapi: () => generateOpenapi({ routers, app })` — без файла; важен тот же `app` |
| Статический сайт только для интегратора | Часто хватает Redoc + файл на диске; пробу — во внутренней сети |

Частый полный обход роутов в проде грузит CPU: наружу чаще **файл на диске + UI читает файл**; в разработке динамическая генерация удобнее. Полный цикл выгрузки — [Генерация OpenAPI](/ru/openapi/).

## Быстрый выбор

| Вопрос | Ответ |
| --- | --- |
| Один UI, нужна проба | Scalar или Swagger |
| Один UI, красивая «брошюра» | Redoc |
| Продукт читает, разработка дергает | Redoc + (Swagger или Scalar) |
| У команды уже закладки / скринкасты Swagger | не меняйте сразу, добавьте Redoc / Scalar |
| Боитесь сканирования в интернете | случайный `uriPrefix` + `enable`, одинаково для всех трёх |

Настройка после установки, `enable` в проде, примеры случайного префикса:

- [Swagger UI](/ru/openapi/swagger-ui)
- [Redoc UI](/ru/openapi/redoc-ui)
- [Scalar UI](/ru/openapi/scalar-ui)
