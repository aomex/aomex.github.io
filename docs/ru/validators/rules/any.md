# rule.any()

Фрагменты JSON **пока без фиксированной формы**: плагин `settings`, аудит `before`/`after`, неизвестные поля во время миграции.

Для общих методов цепочки см. [Общие цепочки](../chain); ниже — только **специфичные для rule** API.

```typescript
import { rule, schema } from '@aomex/common';

export const pluginSchema = schema({
  name: rule.string().required(),
  settings: rule.any().optional(), // [!code highlight]
});
// settings 可以是对象、数组、字符串、数字等常见 JSON 形态
```

- Вывод остается очень широким (около `unknown` / широкого союза — следуйте указаниям компилятора).
- Вы часто все еще сужаете или перепроверяете информацию при чтении `ctx.body`.
- Никаких цепных методов, специфичных для правил.

Предпочитайте [object](./object)/[record](./record), когда вы можете моделировать форму; используйте `rule.any()` для сторонних больших двоичных объектов или JSON администратора во время перехода. Длительное отсутствие `any` ослабляет OpenAPI и TS — ужесточите схему, когда миграция закончится. Для произвольных клавиш с однородными значениями используйте [record](./record), а не `any`.

Для общих цепочек см. [Общие цепочки](../chain); структурированные альтернативы: [record](./record), [oneOf](./one-of), [object](./object).
