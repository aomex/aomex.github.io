# Формат ошибок

Пусть ctx.throw всего сайта (или определенного модуля) станет единым JSON-конвертом вместо обычного текста по умолчанию: повесьте formatError на монтирование, используйте обработчик для определения конечного тела и используйте контент для блокировки типа и OpenAPI. Измените здесь форму, не меняйте сильно тело в app.on('error') - время уже позднее, а с письменным ответом легко побороться.

```typescript
import { rule } from '@aomex/common';
import { formatError, routers, WebApp } from '@aomex/web';

new WebApp({
  // services / logger / language / proxyIP —— 见 [应用入口](/ru/web/)
  mount: [
    formatError({ // [!code focus:13]
      content: { // [!code highlight]
        code: rule.string(),
        message: rule.string(),
      },
      handler(err) {
        return {
          code: err.code ?? 'ERROR',
          message: err.message,
        };
      },
    }),
    routers('./src/routers'),
  ],
});
```

Пучок ` formatError`Повесьте его **снаружи и перед маршрутизаторами**, чтобы любой бросок маршрута попадал в этот обработчик, пока он не перехватывается внутренним слоем.

Форма возвращаемого значения обработчика должна быть выровнена по содержимому;` ctx.throw(403, { code: 'FORBIDDEN' })`Бизнес-код в основном находится в err.code, а копия — в очищенном err.message. Если statusCodes опущен, этот уровень берет на себя **все** 4xx/5xx. по маршруту ` response({ statusCode: 400 })`Когда содержимое не записано, сгенерированный документ часто заимствует форму ошибки внешнего formatError. Если formatError не смонтирован, клиент по-прежнему отображает стандартную текстовую ошибку платформы.

При приеме на себя существующие заголовки текущего ответа обычно очищаются, а затем статус сбрасывается в соответствии с кодом ошибки и отправляется новое тело. Не записывайте err.raw, stack и SQL в возвращаемое значение обработчика — внешнему миру передается только очищенная информация.

## Внутренняя оболочка модуля

Глобальный formatError управляет формой всего сайта по умолчанию; **/admin** или субдомен открытого API требует другой набор имен полей (` error `/` detail `вместо` code `/` message `), соответствующий` Router({ mount: [formatError(...)] })`Повесьте внутрь еще один слой. Внутренняя сторона луковицы сначала ловит бросок, маршрут под этим префиксом использует внутренний конверт, а другие пути по-прежнему используют внешний конверт.

/admin Если вам нужен другой набор имен полей, добавьте еще один слой в Router:

```typescript
import { formatError, Router } from '@aomex/web';

const adminRouter = new Router({ // [!code focus:18]
  prefix: '/admin',
  mount: [
    formatError({ // [!code highlight]
      content: {
        error: rule.string(),
        detail: rule.string().optional(),
      },
      handler(err) {
        return {
          error: err.code ?? 'ADMIN_ERROR',
          detail: err.message,
        };
      },
    }),
    auth.authenticate('bearer'),
  ],
});
```

В луке сначала захватывается внутренняя сторона: /admin/* принимает внутреннюю форму, а другие маршруты продолжают использовать глобальное покрытие.

## частичный захват statusCodes

` statusCodes `Ограничьте **этот слой** formatError, чтобы он обрабатывал только перечисленные коды состояния HTTP (обычно включают только 400, 422 и другие классы проверки). Остальные 4xx/5xx продолжают всплывать к внешнему обработчику, который подходит для разделения труда «унифицированный JSON для проверки ошибок, а бизнес 403 по-прежнему использует глобальный конверт».

Я хочу контролировать только ошибки проверки, а остальные коды оставить на внешнем уровне:

```typescript
formatError({ // [!code highlight]
  statusCodes: [400, 422],
  content: {
    code: rule.string(),
    message: rule.string(),
  },
  handler(err) {
    return {
      code: err.code ?? 'VALIDATION',
      message: err.message,
    };
  },
}),
```

## Работает с маршрутизацией

Используется в маршрутизации ` ctx.throw(status, …)`Активно завершить запрос и пройти по цепочке ошибок: нехватка ресурсов **404**, проверка бизнес-параметра **400**, разрешение **403** и т. д. Второй параметр может быть строкой или с ` code`объект, обработчик formatError из ` err`Получите код и введите копию в содержимое.

```typescript
ctx.throw(404);
ctx.throw(400, 'name required');
ctx.throw(403, { code: 'FORBIDDEN' });
```

Если дело перезаписалось по ошибке или тело выкинуло заново, просто замените всю часть на formatError. Не используйте в действии половину неправильного JSON.

Если вы хотите поместить тело успеха и тело ошибки в один слой `{ success, data, statusCode }`, Внешний HTTP имеет фиксированное значение 200, см. [Конверт для ответа](/ru/web/envelope) (часто в сочетании с formatError).
