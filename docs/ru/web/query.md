# Строка запроса

Объявите параметры ?page=1&keyword= для интерфейса GET (или другой команды с запросом): повесьте query() в монтировании маршрута и используйте [валидаторы](/ru/validators/) для ограничения типа и области действия. После прохождения таможенного оформления ctx.query используется непосредственно в бизнесе; если таможенное оформление не пройдено, автоматически отобразится **400** и никаких действий предпринято не будет.

```typescript
import { rule } from '@aomex/common';
import { query, Router } from '@aomex/web';

export const router = new Router();

router.get('/users', { // [!code focus:13]
  mount: [
    query({ // [!code highlight]
      page: rule.int().min(1).default(1),
      size: rule.int().min(5).max(50).default(10),
      keyword: rule.string().optional(),
    }),
  ],
  action: async (ctx) => {
    const { page, size, keyword } = ctx.query;
    ctx.send({ page, size, keyword, items: [] });
  },
});
```

Пример запроса: GET /users?page=2&size=20&keyword=ada.

После отключения query() ctx.query содержит только объявленные ключи; default() делает параметр по умолчанию обязательным значением/строкой типа (например, страница всегда имеет номер). Тип поля option() не определен. Когда query() не смонтирован в методе монтирования, только ` ctx.request.query`Такой более широкий тип — не используйте его напрямую как доверенные данные в бизнесе. Если проверка не пройдена, никаких действий предпринято не будет, а ответом будет **400**.

Не пишите от руки в действии ` Number(ctx.request.query.page)`—— Отсутствие связи с OpenAPI и форматами ошибок проверки, а типы не будут автоматически сужены.

## Схема списка повторного использования

Совместно используется несколькими интерфейсами списков ` page`/` size `/` q `Когда получите поле запроса` src/schemas/*.schema.ts `, в маршрутизации` query(listQuerySchema)`Цитирую то же самое. Если вы измените лимит подкачки или значение по умолчанию только в одном месте, OpenAPI будет следовать тому же набору описаний.

Несколько интерфейсов списков совместно используют подкачку / q При поиске ` src/schemas/*.schema.ts`:

```typescript
// src/schemas/list-query.schema.ts
import { schema, rule } from '@aomex/common';

export const listQuerySchema = schema({
  page: rule.int().min(1).default(1),
  size: rule.int().max(100).default(20),
  q: rule.string().trim().optional(),
});
```

```typescript
// src/routers/user.ts
import { query, Router } from '@aomex/web';
import { listQuerySchema } from '../schemas/list-query.schema.js';

const router = new Router();

router.get('/users', { // [!code focus:6]
  mount: [query(listQuerySchema)], // [!code highlight]
  action: async (ctx) => {
    const { page, size, q } = ctx.query;
    ctx.send(await searchUsers({ page, size, q }));
  },
});
```

Поля сортировки перечислений:

```typescript
sort: rule.enum(['name', 'createdAt'] as const).default('createdAt'),
```

Инструкции OpenAPI вешаются на правила или маршруты:

```typescript
page: rule.int().min(1).docs({ description: '页码，从 1 起' }),
```

## Отдел работы с телом/параметрами

Три источника входных параметров имеют смешанные обязанности: **query** выполняет фильтрацию и разбиение по страницам (идемпотентный GET), **params** идентифицирует ресурсы в пути, а **body** переносит созданный/обновляемый объект. Неправильное расположение приведет к тому, что кеш, журналы и OpenAPI не будут соответствовать фактической семантике.

| источник | Типичное использование |
| --- | --- |
| **запрос** | Фильтрация, пейджинг, сортировка — идемпотентный GET |
| **параметры** | Идентификатор ресурса в пути |
| **тело** | Сущности для POST/PUT/PATCH |

Если большой раздел JSON фильтруется с помощью принудительного запроса, URL-адрес взорвется, и ключом кэша будет сложно управлять — этот тип можно изменить на POST +` body()`, принимая цену отсутствия кэширования как идемпотентный GET. Создание POST с использованием запроса для передачи большого JSON также противоречит соглашению.

::: tip
Клиенты страниц списка часто передают несколько параметров отслеживания; не делайте запрос слишком строгим или избыточным и обязательным, иначе стыковка B2B легко получит 400 ошибок. default() позволяет типу иметь значение по умолчанию, но исходный URL-адрес в журнале доступа может не иметь ?page=1.
:::
