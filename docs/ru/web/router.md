# Маршрутизация HTTP

Разбейте `src/routers ` по доменам: каждый файл экспортирует ` Router `, регистрируйте action через ` get ` / ` post `; один раз смонтируйте на ` WebApp ` через ` routers('./src/routers')`.


```typescript
// src/routers/user.ts
import { Router } from '@aomex/web';

export const router = new Router();

const users = [
  { id: 1, name: 'Ada' },
  { id: 2, name: 'Bob' },
];

router.get('/users', { // [!code focus:5]
  action: async (ctx) => {
    ctx.send(users);
  },
});

router.get('/users/count', {
  action: async (ctx) => {
    ctx.send({ count: users.length });
  },
});
```

Подключитесь к приложению:

```typescript
import { routers, WebApp } from '@aomex/web';

new WebApp({
  // services、logger、language、proxyIP …
  mount: [routers('./src/routers')], // [!code highlight]
});
```

При тестировании или переключении функций вы можете передавать конкретные примеры без сканирования каталога:

```typescript
import { userRouter } from './routers/user.js';
import { postRouter } from './routers/post.js';

mount: [routers([userRouter, postRouter])],
```

После того, как query()/body()/params()/response() установлены в монтировании одного маршрута, ctx в действии объединит соответствующие типы полей. **Уровень метода** монтирование влияет только на текущий интерфейс; **Уровень маршрутизации**` Router({ mount: [...] })`Действительно для всех методов в этом файле.

```typescript
router.get('/users', { // [!code focus:11]
  mount: [
    middleware.web<{ tenant: string }>(async (ctx, next) => { // [!code highlight]
      ctx.tenant = ctx.request.headers['x-tenant'] as string;
      await next();
    }),
  ],
  action: (ctx) => {
    ctx.tenant;
  },
});

router.get('/users/:id', {
  action: (ctx) => {
    ctx.tenant; // 类型上不存在
  },
});
```

## префикс

` Router({ prefix })`Добавьте фиксированный префикс ко **всем** путям регистрации в этом файле, чтобы избежать каждого ` router.get`Все написано от руки `/users`. Переключение версий (`/v1`→`/v2`) или при разделении URL по домену измените только один параметр конструкции.

```typescript
import { rule } from '@aomex/common';
import { params, Router } from '@aomex/web';

export const router = new Router({ prefix: '/users' }); // [!code highlight]

router.get('/', { // [!code focus:5]
  action: async (ctx) => {
    ctx.send([]);
  },
});

router.get('/:id', {
  mount: [params({ id: rule.int().min(1) })],
  action: async (ctx) => {
    ctx.send({ id: ctx.params.id });
  },
});
```

Конечный путь = префикс + uri при регистрации (лишние слэши будут нормализованы). При отладке ошибки 404 не смотрите только на нее. ` router.get('/:id')`, сначала необходимо указать полный путь префикса.

OpenAPI сгруппировано по домену ` Router({ docs: { tags: ['User'] } })`;Один маршрут ` docs.summary`Можно накрыть.

## Крепление уровня маршрута

уровень маршрутизации ` Router({ mount: [...] })`Вешайте middleware на все методы всего файла: вся группа должна залогиниться, записывать аудиты или единообразно вешать запрос. Используйте эту запись, когда используется значение по умолчанию, а не в каждом ` router.get`Повторное монтирование здесь избавляет от проблем.

Когда весь файл необходимо зарегистрировать и проверить:

```typescript
new Router({
  prefix: '/admin',
  mount: [auth.authenticate('bearer')],
});
```

Монтирование на уровне маршрута влияет на **все** методы в этом файле; публичный интерфейс и интерфейс для входа в систему не должны быть втиснуты в один и тот же маршрутизатор — разделите файл на общедоступной странице или измените монтирование/пропуск на уровне метода.

## Монтирование по одному маршруту, документы, отключено

**Монтирование на уровне метода** применяется только к этому маршруту: проверка входных параметров (запрос/тело/параметры/ответ), аутентификация с одним интерфейсом и т. д. При объединении с монтированием на уровне маршрута сначала перейдите на уровень маршрутизации, а затем на уровень метода.

**отключено** позволяет **не регистрировать** определенный маршрут при запуске (нет сопоставления, нет действий). Часто используемые переменные среды или переключатели функций отключают полуфабрикаты интерфейсов, что безопаснее, чем оставлять 501 в производстве.

**docs** Напишите описание этого маршрута в OpenAPI (например,` summary `).` Router({ docs: { tags } })`Ответственный за группировку; отдельные маршрутные документы могут включать заголовки и описания и включаются в контракт вместе с [response()](/ru/web/response) при создании документов.

```typescript
import { rule } from '@aomex/common';
import { query, response, Router } from '@aomex/web';

router.get('/users', { // [!code focus:11]
  disabled: process.env['FEATURE_USERS'] !== '1', // [!code highlight]
  mount: [
    query({ page: rule.int().min(1).default(1) }),
    response({ statusCode: 200, content: rule.array({ id: rule.int() }) }),
  ],
  docs: { summary: '用户列表' }, // [!code highlight]
  action: async (ctx) => {
    ctx.send([]);
  },
});
```

Метаданные OpenAPI подробно описаны в [Плагин OpenAPI](/ru/plugins/openapi).

Параметры одного пути:

```typescript
router.get('/users/:id', {
  mount: [params({ id: rule.int().min(1) })], // [!code highlight]
  action: async (ctx) => {
    ctx.send({ id: ctx.params.id });
  },
});
```

Когда параметр пути не связан с params(),` ctx.request.params `Все они являются строками, и в бизнесе «1» и 1 легко спутать.

## HTTP-метод

каждый` router.<method>(uri, { ... })`Связывает HTTP-команду; порядок регистрации не влияет на сопоставление, статические сегменты и буквенные пути по-прежнему имеют приоритет. `:param`.

| метод | иллюстрировать |
| --- | --- |
| ` get ` | ` GET `;**HEAD** с тем же именем` GET `Общие матчи |
| ` post `/` put `/` patch `/` delete ` | Соответствующий глагол |
| ` all ` | Все вышеперечисленные глаголы |
| ` customize ` | Массив необязательных глаголов |

` customize `Принимать несколько команд (проверка GET, квитанция POST и т. д.) по одному и тому же пути одновременно, стандартно.` get `/` post `Каждая регистрация будет занимать два маршрута, что тоже сложно обслуживать. Он обычно используется для сторонних веб-перехватчиков, проверок работоспособности и зондирования:

Сторонний вебхук использует настройку:

```typescript
router.customize(['GET', 'POST'], '/webhook', { // [!code highlight]
  action: async (ctx) => {
    ctx.send({ ok: true });
  },
});
```

## Написание пути

При регистрации uri **литеральный сегмент** имеет приоритет над `:param `,так `/users/count ` не будет `/:id ` Есть. Имя ключа именованного параметра должно быть таким же, как ` params()` Поля в согласованы.

| Метод письма | значение |
| --- | --- |
| `/users/:id ` | именованные параметры ` id ` |
| `/users/count ` и `/users/:id ` сосуществовать | Буквальные пути имеют приоритет,`:id ` Не буду это есть ` count`;Не ждите, что последовательность регистрации спасет положение. Если вы можете написать статический сегмент, просто напишите статический сегмент. |

Когда glob сканирует каталог, старайтесь помещать только экспорт маршрутизатора. Слишком много разных файлов и сложно разобраться "почему не зарегистрировано".
