# SSE: серверный push

Создайте интерфейс GET, который «сервер продолжает нажимать вниз, а браузер использует EventSource для прослушивания»: вызовите ctx.sse() в действии и используйте поток или отправку для выдачи событий. Подходит для уведомлений, индикаторов выполнения и обновлений рынка; рассмотрите WebSocket для двунаправленных беспорядочных кадров.

```typescript
import { Router } from '@aomex/web';

export const router = new Router();

router.get('/events', { // [!code focus:13]
  action: async (ctx) => {
    const sse = ctx.sse({ retry: 3_000 }); // [!code highlight]
    await sse.stream(async (emit, signal) => {
      for await (const item of watchEvents({
        after: sse.lastEventId,
        signal,
      })) {
        emit({ id: String(item.id), event: 'item', data: item });
      }
    });
  },
});
```

Сначала используйте поток: сигнал прервется, когда клиент отключится, и автоматически завершится, когда итерация закончится, что сэкономит вам много таймеров закрытия/очистки.

` ctx.sse()`и ` ctx.response.sse()`Эквивалент; его необходимо вызывать, когда заголовок ответа не записан, иначе будет выдана ошибка. SSE занимает весь ответ, не отправляйте ctx.send JSON в конце того же маршрута. После открытия код состояния 200, тип контента: text/event-stream. Данные испускания/отправки будут сериализованы в формате JSON при передаче объекта; LastEventId берется из заголовка запроса и обычно не определен для первого соединения.

## сердцебиение и повторите попытку

Длинные соединения браузера могут быть легко отключены путем обратной генерации как бездействующие. **сердцебиение** периодически подталкивает к тому, чтобы выжить; **Повторить** рекомендует количество миллисекунд после отключения клиента для повторного подключения (записывается в параметрах SSE при установке соединения). Вы можете отключить пульс для локального короткого тестирования; проверьте оба производственных потока через Nginx и CDN.

Длинные соединения сохраняются при прохождении через Nginx и CDN; местное краткосрочное тестирование может отключить сердцебиение:

```typescript
const sse = ctx.sse({
  heartbeat: 10_000,
  retry: 3_000,
});
```

| Параметры | По умолчанию/Привычка | когда использовать |
| --- | --- | --- |
| ` heartbeat ` | Обычно около 15 секунд | Длительная поддержка соединения через Nginx и CDN; местный короткий тест может` heartbeat: false ` |
| ` retry ` | Нет в наличии | Есть надежда, что браузер будет повторно подключаться через миллисекундные интервалы после отключения (постоянная настройка потока уведомлений).`3000`) |

## Поле одного события

каждый раз ` send`/` emit `Может принимать имя события, идентификатор, необязательную однократную повторную попытку и полезные данные. Данные объекта будут автоматически сериализованы в формате JSON; когда установлен **id**, браузер повторно подключится` Last-Event-ID `, чтобы облегчить дальнейшую загрузку.

| Поле | когда использовать |
| --- | --- |
| ` data ` | Полезная нагрузка; Объект Авто JSON |
| ` event ` | Несколько событий сосуществуют (` job `/` progress `/` ready `), внешние мониторы по имени |
| ` id ` | Возобновление передачи после разрыва связи; повторное соединение` Last-Event-ID ` |
| ` retry ` | Временно изменить интервал переподключения в одном событии |

```typescript
sse.send({ data: { hello: 'world' } });
sse.send({ event: 'ready' });
sse.send({
  id: '42', // [!code highlight]
  event: 'job',
  retry: 5_000,
  data: 1,
});
```

## поток, продолжение и окончание

` stream `Оберните «чтение восходящего потока во время отправки» в жизненный цикл: **сигнал** прерывается, когда клиент отключается, и он завершится, когда итерация завершится, устраняя необходимость в рукописных таймерах и закрытии.` lastEventId `Из заголовка запроса используйте его, чтобы сделать вывод об определенном событии;` onClose `Отпустите подписку и запишите аудит.

```typescript
await sse.stream(async (emit, signal) => {
  // emit 等同 sse.send；signal 断开即 abort
});
```

| член | Как использовать его обычным способом |
| --- | --- |
| ` lastEventId ` | Продолжайте нажимать после этого идентификатора |
| ` signal ` | Передайте его подписке Redis и просмотру очереди, и клиент остановится, даже если он перейдет в восходящий поток. |
| ` onClose(fn)` | Освободите подписку и запишите аудит |
| ` close()` | Автоматически отключать поток после выполнения задачи;` stream `Он автоматически отрегулируется, когда закончится. |

```typescript
const after = sse.lastEventId; // [!code highlight]
sse.onClose(() => {
  subscription.unsubscribe();
});
sse.close();
```

Когда соединение закрыто или недоступно для записи, отправка будет молча игнорироваться — не рассматривайте ее как «определенную доставку». Чтобы возобновить передачу после отключения, установите для события стабильный идентификатор. В противном случае LastEventId не будет совпадать, и соединение будет перезапущено.

::: warning
Когда длительное соединение реверсируется Nginx и т. д., в дополнение к X-Accel-Buffering:no фреймворка еще необходимо настроить тактовый импульс и тайм-аут обратной буферизации, иначе он легко обрежется при простое.
:::

## С ответом(), OpenAPI

OpenAPI должен знать, что этот выход GET ` text/event-stream`, поэтому смонтируйте его в mount ` response({ contentType: 'text/event-stream', ... })`. Это обслуживает только документы и типы и не может заменить те, которые находятся в действии. ` ctx.sse()`Написать кадр.

```typescript
import { rule } from '@aomex/common';
import { response } from '@aomex/web';

response({
  statusCode: 200,
  contentType: 'text/event-stream', // [!code highlight]
  content: rule.string(),
  description: 'SSE 事件流',
});
```

Это помогает только в документации и подсказках по типу, но не является заменой**. ` ctx.sse()` Протокол кадра. middleware сжатия обычно пропускает поток текста/событий, см. [Compress](/ru/plugins/compress).

EventSource может быть только GET. При использовании файлов cookie на разных сайтах необходимо настроить [CORS](/ru/plugins/cors).
