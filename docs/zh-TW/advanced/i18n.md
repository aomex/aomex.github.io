# 業務國際化

[WebApp.language](/zh-TW/web/#language) / [ConsoleApp.language](/zh-TW/console/#language) 管的是**框架**側：body / query 校驗失敗、內建提示用哪種語言。產品問候語、業務錯誤碼、郵件模板不在那一套裡——要自己建文案包，用 `i18n.t(...)` 拼對外字串。

兩套職責分開：當前語言仍由 App 驅動（一般不用自己解析 `Accept-Language`）；產品文案別塞進框架 `language` 配置，升級框架時才好合併。

下面從「一張中文母本」做到「路由裡能 t、缺鍵能在型別階段發現」。

## 第一步：定母本鍵樹

先寫中文（或你的主語言）包，用 `I18n.define` 定下所有鍵。其它語言必須對齊這棵樹。

```typescript
// src/i18n/locales/zh-cn.ts
import { I18n } from '@aomex/common';

export const zh = I18n.define({ // [!code highlight]
  greeting: '你好，{{name}}',
  errors: {
    notFound: '找不到资源',
    quotaExceeded: '今日额度已用完',
  },
});
```

`{{name}}` 是模板佔位符，呼叫 `t` 時傳入的引數名必須一致，否則執行時會露出佔位符或空串。

## 第二步：第二語言用 satisfies 對齊

不要手寫一份「看起來差不多」的物件——用 `I18n.satisfies(zh).define`，缺鍵、多鍵往往在**型別**上報錯，比上線才發現漏翻譯省心。

```typescript
// src/i18n/locales/en-us.ts
import { I18n } from '@aomex/common';
import { zh } from './zh-cn.js';

export const en = I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'Hello, {{name}}',
  errors: {
    notFound: 'Not found',
    quotaExceeded: 'Daily quota exceeded',
  },
});
```

試著刪掉 `errors.notFound`：編輯器應立刻提示與母本不一致。

## 第三步：createI18n 組裝

```typescript
// src/i18n/index.ts
import { createI18n } from '@aomex/common';
import { zh } from './locales/zh-cn.js';
import { en } from './locales/en-us.js';

export const i18n = createI18n({
  zh,
  en,
  load: (file) => { // [!code highlight]
    return import(new URL(`./locales/${file}.js`, import.meta.url).href);
  },
});
```

- `zh` / `en`：啟動時同步打包進去的語言  
- `load`：按需非同步語言（下一步）；檔名規則見下  

目錄習慣：`locales/` 只放文案，`index.ts` 只組裝——和框架包內 i18n 結構一致，後人好找。

## 第四步：在路由裡用起來

```typescript
import { rule } from '@aomex/common';
import { query, Router } from '@aomex/web';
import { i18n } from '../i18n/index.js';

const router = new Router();

router.get('/hello', {
  mount: [query({ name: rule.string().default('guest') })],
  action: async (ctx) => {
    ctx.send({
      message: i18n.t('greeting', { name: ctx.query.name }), // [!code highlight]
    });
  },
});

router.post('/consume', {
  action: async (ctx) => {
    if (!(await hasQuota(ctx))) {
      ctx.throw(429, i18n.t('errors.quotaExceeded'));
    }
  },
});
```

`t` 的第一個引數是鍵路徑（`'errors.quotaExceeded'`），第二個是模板引數。鍵寫錯時看補全；和 App 當前語言的對應關係由框架側歸一，語言碼配置寫 `zh-CN` / `en-US` 這種連字元形式。

改一下 App 的 `language`（或請求頭協商），再打 `/hello`，問候語應跟著變——**不必**在 action 裡自己讀 `Accept-Language`。

## 第五步：按需載入第三種語言

小語種不想打進主包時，放到 `load` 能解析到的檔案：小寫檔名 + **`export default`**。

```typescript
// src/i18n/locales/ja-jp.ts
import { I18n } from '@aomex/common';
import { zh } from './zh-cn.js';

export default I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'こんにちは、{{name}}',
  errors: {
    notFound: 'リソースが見つかりません',
    quotaExceeded: '本日の上限に達しました',
  },
});
```

::: warning
按需檔案必須 `export default`。寫成 `export const ja = ...` 會對不上 `load`。  
裸指令碼 / 單測裡若語言還沒載入完，先按型別提示呼叫 `ensureI18nLanguage`（或專案封裝），再 `t`。
:::

## 和框架 language、自定義驗證器的邊界

| 文案型別 | 放哪裡 |
| --- | --- |
| `rule.string()` 失敗的內建提示 | App `language` |
| 「今日額度已用完」等產品句 | 本頁 `i18n` |
| 自定義驗證器 `deny` 要產品句 | `deny` 裡自己 `import { i18n }` 再 `t` |

見 [自定義驗證器](/zh-TW/advanced/validator)。不要把業務鍵塞進框架語言表，也不要用框架表冒充產品文案。

## 配錯時你會看到什麼

| 現象 | 多半是 |
| --- | --- |
| 第二種語言型別報錯 | 沒走 `satisfies(zh).define`，或鍵與母本不一致 |
| 執行露出 `{{name}}` | `t` 引數名和模板不一致 |
| 非同步語言一直是回退語 | 檔名大小寫 / 沒用 `export default` / 未等載入完成 |
| 校驗 400 仍是中文、業務句是英文 | 正常：兩套表；分別查 App language 與 `i18n` |
