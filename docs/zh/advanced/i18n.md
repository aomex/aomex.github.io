# 业务国际化

[WebApp.language](/zh/web/#language) / [ConsoleApp.language](/zh/console/#language) 管的是**框架**侧：body / query 校验失败、内置提示用哪种语言。产品问候语、业务错误码、邮件模板不在那一套里——要自己建文案包，用 `i18n.t(...)` 拼对外字符串。

两套职责分开：当前语言仍由 App 驱动（一般不用自己解析 `Accept-Language`）；产品文案别塞进框架 `language` 配置，升级框架时才好合并。

下面从「一张中文母本」做到「路由里能 t、缺键能在类型阶段发现」。

## 第一步：定母本键树

先写中文（或你的主语言）包，用 `I18n.define` 定下所有键。其它语言必须对齐这棵树。

```typescript
// src/i18n/locales/zh-cn.ts
import { I18n } from '@aomex/common';

export const zh = I18n.define({ // [!code highlight]
  greeting: '你好，{{name}}',
  errors: {
    notFound: '找不到资源',
    quotaExceeded: '今日额度已用完',
  },
});
```

`{{name}}` 是模板占位符，调用 `t` 时传入的参数名必须一致，否则运行时会露出占位符或空串。

## 第二步：第二语言用 satisfies 对齐

不要手写一份「看起来差不多」的对象——用 `I18n.satisfies(zh).define`，缺键、多键往往在**类型**上报错，比上线才发现漏翻译省心。

```typescript
// src/i18n/locales/en-us.ts
import { I18n } from '@aomex/common';
import { zh } from './zh-cn.js';

export const en = I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'Hello, {{name}}',
  errors: {
    notFound: 'Not found',
    quotaExceeded: 'Daily quota exceeded',
  },
});
```

试着删掉 `errors.notFound`：编辑器应立刻提示与母本不一致。

## 第三步：createI18n 组装

```typescript
// src/i18n/index.ts
import { createI18n } from '@aomex/common';
import { zh } from './locales/zh-cn.js';
import { en } from './locales/en-us.js';

export const i18n = createI18n({
  zh,
  en,
  load: (file) => { // [!code highlight]
    return import(new URL(`./locales/${file}.js`, import.meta.url).href);
  },
});
```

- `zh` / `en`：启动时同步打包进去的语言  
- `load`：按需异步语言（下一步）；文件名规则见下  

目录习惯：`locales/` 只放文案，`index.ts` 只组装——和框架包内 i18n 结构一致，后人好找。

## 第四步：在路由里用起来

```typescript
import { rule } from '@aomex/common';
import { query, Router } from '@aomex/web';
import { i18n } from '../i18n/index.js';

const router = new Router();

router.get('/hello', {
  mount: [query({ name: rule.string().default('guest') })],
  action: async (ctx) => {
    ctx.send({
      message: i18n.t('greeting', { name: ctx.query.name }), // [!code highlight]
    });
  },
});

router.post('/consume', {
  action: async (ctx) => {
    if (!(await hasQuota(ctx))) {
      ctx.throw(429, i18n.t('errors.quotaExceeded'));
    }
  },
});
```

`t` 的第一个参数是键路径（`'errors.quotaExceeded'`），第二个是模板参数。键写错时看补全；和 App 当前语言的对应关系由框架侧归一，语言码配置写 `zh-CN` / `en-US` 这种连字符形式。

改一下 App 的 `language`（或请求头协商），再打 `/hello`，问候语应跟着变——**不必**在 action 里自己读 `Accept-Language`。

## 第五步：按需加载第三种语言

小语种不想打进主包时，放到 `load` 能解析到的文件：小写文件名 + **`export default`**。

```typescript
// src/i18n/locales/ja-jp.ts
import { I18n } from '@aomex/common';
import { zh } from './zh-cn.js';

export default I18n.satisfies(zh).define({ // [!code highlight]
  greeting: 'こんにちは、{{name}}',
  errors: {
    notFound: 'リソースが見つかりません',
    quotaExceeded: '本日の上限に達しました',
  },
});
```

::: warning
按需文件必须 `export default`。写成 `export const ja = ...` 会对不上 `load`。  
裸脚本 / 单测里若语言还没加载完，先按类型提示调用 `ensureI18nLanguage`（或项目封装），再 `t`。
:::

## 和框架 language、自定义验证器的边界

| 文案类型 | 放哪里 |
| --- | --- |
| `rule.string()` 失败的内置提示 | App `language` |
| 「今日额度已用完」等产品句 | 本页 `i18n` |
| 自定义验证器 `deny` 要产品句 | `deny` 里自己 `import { i18n }` 再 `t` |

见 [自定义验证器](/zh/advanced/validator)。不要把业务键塞进框架语言表，也不要用框架表冒充产品文案。

## 配错时你会看到什么

| 现象 | 多半是 |
| --- | --- |
| 第二种语言类型报错 | 没走 `satisfies(zh).define`，或键与母本不一致 |
| 运行露出 `{{name}}` | `t` 参数名和模板不一致 |
| 异步语言一直是回退语 | 文件名大小写 / 没用 `export default` / 未等加载完成 |
| 校验 400 仍是中文、业务句是英文 | 正常：两套表；分别查 App language 与 `i18n` |
